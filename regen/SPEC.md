# 卡片规格 v3 —— 速读卡

> 目标：**5 分钟读懂一篇论文在干什么**。读者是同行（CV / 多模态 / 医学影像方向的研究生），
> 不需要从零科普，但需要在不读原文的前提下回答四个问题：
> ① 这论文解决什么问题？② 它怎么做的？③ 到底好了多少？④ 能不能为我所用？

v1 卡片（`v` 缺省或 1）是**审稿意见卡**：短评价 + 打分 + 挑毛病，读不出内容。
v2 卡片补了 `task/problem/idea/how`，但还是"提纲式"，缺真实数字与结构。
**v3 是对标 papernotes 一类速读站点的完整结构。**

---

## 一、阅读顺序（渲染顺序 = 字段顺序）

| # | 区块 | 字段 | 说明 |
|---|---|---|---|
| 1 | 一句话总结 | `tldr` | **首屏大字**。浓缩"问题 + 做法 + 结果数字"。这是全卡最重要的一段 |
| 2 | 任务定义 | `task` | 输入什么 → 输出什么。**不得出现方法名**，让外行也知道任务边界 |
| 3 | 研究背景与动机 | `motivation[]` | 2–5 条，每条一个失效点/痛点，带证据或数据 |
| 4 | 核心思想 | `idea` | 一段话讲清"关键洞察 + 对应机制"，读完能复述 |
| 5 | 方法详解 | `method_overview[]` + `designs[]` | 前者是流水线阶段，后者是值得单独讲的设计（含公式、超参、拐点） |
| 6 | 实验设定 | `setup` | 基座模型、数据集、对比方法、评价方式 |
| 7 | 实验关键数据 | `results_table` | **必须有真表**：模型 × 指标 × 数字，主结果或消融 |
| 8 | 关键数字 | `nums[]` | 表格放不下的关键数字（超参拐点、消融差值） |
| 9 | 关键发现 | `findings[]` | 从数据里读出来的结论，不是复述表格 |
| 10 | 亮点与洞察 | `insights[]` | 可迁移的做研究的方法论 / 值得抄的写法 |
| 11 | 局限与展望 | `limits[]` | 分点，每条要具体到"哪个实验没做/哪个超参没解决" |
| 12 | 与我的研究 | `why_me` | 与贺铖（CV / 多模态可靠性 / 医学影像）的关系；无关则留空 |
| 13 | 评分 | `scores` | 四维 + 综合，沿用 v1 |
| 14 | 相关工作与启发 | `related[]` | 2–3 条：谁最相关、差在哪（论文原文对比的方法优先） |

---

## 二、字段规格

### 字符串字段

| 字段 | 类型 | 长度 | 硬性要求 |
|---|---|---|---|
| `tldr` | str | **90–300 字** | 必须含至少 1 个**带方向的数字**（如 3.52→3.80）。可按"现象 → 机制 → 结果"三段写 |
| `task` | str | 20–70 字 | 输入→输出。**禁出现方法名、禁评价词** |
| `idea` | str | 40–160 字 | 讲"为什么这么设计有效"，不是复述模块名 |
| `setup` | str | 60–320 字 | 基座/数据/对比/指标，四要素齐全 |
| `why_me` | str | 0–150 字 | 无关联必须留空字符串 |

### 列表字段（每条 `{"h": 小标题, "d": 正文}`）

| 字段 | 条数 | `d` 长度 | 内容要求 |
|---|---|---|---|
| `motivation` | 2–5 | 25–180 字 | 每条的 `h` 是一个**判断句**（"转折词 = 高熵 = 不看图"），不是名词（"研究动机"） |
| `method_overview` | 2–5 | 25–200 字 | 阶段名 + 该阶段干什么、产出什么 |
| `designs` | 2–5 | 40–300 字 | 关键设计：机制 + 为什么有效 + 超参/公式。**公式用纯文本写**（`ẽ_t = Σ_v p_t[v]·e(v)`） |

### 表格字段 `results_table`

```json
{"cols": ["方法", "VStar", "MMHalu"],
 "rows": [["Base", "66.5", "3.52"], ["+ Ours", "71.2", "3.80"]],
 "note": "MMHalu 为 0–6 分模型评分，其余为准确率"}
```

- `cols` ≥ 3 列（含首列方法名），`rows` 2–10 行；
- 每行长度必须等于 `cols` 长度；单元格用字符串，数字保留原文精度；
- **至少一半的行含阿拉伯数字**；
- 选**主结果表**或最能说明问题的那张消融表，不要两表都塞。

### 其它

- `nums[]`：2–5 条，每条 ≤ 80 字且**必须含数字**；写超参拐点、消融差值这类表格装不下的。
- `findings[]`：2–5 条，每条 ≤ 180 字。必须是从数据得出的判断，且**至少 3 条含数字**。
- `insights[]`：2–4 条，每条 ≤ 180 字。方法论层面可迁移的东西（怎么写论文、怎么设计消融）。
- `limits[]`：2–5 条，每条 ≤ 180 字。具体到"哪个实验没做/哪个超参没解决/哪个证据只是相关性"。
- `related[]`：2–3 条，`h` 是方法名 + 一句定位，`note` 说清"与本文差在哪"。若该条是分析者的延伸而非论文原文讨论，必须标注"（此条为延伸，非论文原文讨论）"。

## 三、写作硬规则

1. **先给数字，再给形容词。** "显著提升"一律改成"3.52→3.80"，无数字可写时说明原因。
2. **`tldr` 不许下判决。** 不要"但创新有限"这类话；优缺点只出现在 `limits` 与 `insights`。
3. **`task` 与 `motivation` 里不许出现本文方法名**（避免"用 LEAD 解决 LEAD 的问题"这种空转）。
4. **区分"论文说的"与"我判断的"**：`findings` 是论文结论，`insights` / `related` 的分析要能看出是分析者的观点。
5. **不许脑补实验**：没在正文出现的数字、数据集名、对比方法，一律不写。不确定就少写一条。
6. **`limits` 不许写"未来可扩展到更多数据集"这种空话**，要落到具体缺失：哪个基座没测、哪个超参没自适应、哪个因果链只有相关性。
7. **术语保留英文原形**（token entropy、MMHalu、Pass@k），不要硬译。
8. **同一篇的 `tldr` 与 `task` 不重复**：`task` 定义问题，`tldr` 讲这篇怎么解、解到什么程度。

## 四、反面 → 正面

**v1 反面**（21 字，全篇无信息）
> LLT框架提升零样本时序动作定位，但创新有限

**v3 正面**（同一篇应有）
> 零样本时序动作定位要回答"视频里从没见过的动作在哪个时间段"。现有方法把视频级标签硬分给片段，导致背景片段被当成动作。LLT 用大模型生成的描述做片段级伪标签，再用对比学习把片段特征与文本对齐，THUMOS14 上未见过类别 mAP 从 21.3 提到 26.8，超过需要微调的零样本基线。

## 五、验收

```bash
python regen/validate.py "regen/out/*/*.json"
```

`validate.py` 会拦住：长度越界、缺字段、表格列数不齐、数字不足、`task` 出现方法名。
另外要求：**抽 10 张人工读**，若 8 张能在 2 分钟内说清"这篇在做什么"，才算这批合格。
