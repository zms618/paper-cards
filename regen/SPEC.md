# 卡片 v2 规格（Card Spec v2）

## 为什么改

v1 卡片的问题（已量化，21,332 篇全站统计）：

| 指标 | 现状 | 后果 |
|---|---|---|
| `one_line` 平均长度 | 27 字（中位 26） | 只能容纳"方法名 + 效果判断" |
| `one_line` 含评价/转折词 | **54%**（"但创新有限""证据不足"） | 读者先读到审判，读不到内容 |
| 全卡没有任何数字 | **19%** | 无法判断到底好多少 |
| 有"问题/动机"字段 | 无 | 不知道它在跟谁比、为什么需要它 |
| 有"任务定义"（输入→输出） | 无 | 跨领域读者看不懂在做什么 |

结论：v1 是**审稿意见卡**（打分 + 挑毛病），不是**理解卡**。要让非本方向的读者 30 秒知道"这篇在干什么"，必须补 3 样东西：任务定义、动机（之前怎么不行）、带数字的结果。

## 字段定义

必填，除 `why_me`。中文正文，专有名词保留英文。长度是硬约束，validator 会拦。

| 字段 | 类型 | 长度 | 写什么 | 禁止 |
|---|---|---|---|---|
| `task` | str | 20–60 字 | 这是什么任务：输入是什么、输出是什么、应用场景 | 禁写方法名、禁写效果评价、禁用"提出/设计"开头 |
| `problem` | str | 60–160 字 | 之前的方法具体怎么不行（机制层面的不足，不是"效果不够好"）、作者观察到什么现象 | 禁空话"性能有待提升" |
| `idea` | str | 40–100 字 | 核心想法一句话，说清"为什么这么做能解决 problem" | 禁罗列模块 |
| `how` | str | 120–300 字 | 具体实现：几个关键步骤/模块/损失/超参，按 ①②③ 组织 | 禁只写名词短语 |
| `setup` | str | 60–160 字 | 基座模型 / 数据集 / 评价指标 / 对比基线 | 禁省略数据集名 |
| `nums` | list[str] | 2–4 条，每条 ≤60 字 | 关键结果，**每条必须含阿拉伯数字**，写清"在哪设什么上、从多少到多少、涨了多少" | 禁"显著提升""效果更好" |
| `limits` | str | 60–200 字 | 作者没解决的、或证据不足的，要指到具体实验/设定 | 禁"未来工作可以..."式复述作者 |
| `why_me` | str | ≤100 字，可空 | 与贺铖研究（CV/多模态可靠性/分布偏移/医学影像）的接口 | 不许硬凑，无关就留空 |

保留字段：`scores`（novelty/depth/evidence/relevance/overall）、`one_line`（此时允许评价，作为"一句话结论"）、`innovations`/`takeaways`/`weaknesses`（v2 下作为补充证据，可精简）。

## 写作规则（给生成模型的硬约束）

1. **先讲人话，再上术语**：`task` 和 `problem` 里出现的第一个专业词，必须在同句给出 8 字内的解释。
2. **数字必须来自原文**：只允许抄正文/表格里出现过的数值，禁止换算、禁止四舍五入到整数后再放大。原文没报就写"未报告"。
3. **`task` 里不许出现方法名**（LEAD / SCFR / TG-WSPIS 之类），方法名只在 `idea` 之后出现。
4. **禁止在 `task`/`problem` 里下结论**（"效果有限""创新不足"这类判断只允许出现在 `limits`/`one_line`）。
5. **`limits` 必须是质疑，不是复述**：作者自己说的 future work 不算，要指出"这个实验证据撑不起这个 claim"。
6. 全文不超过 900 字；宁短勿水。信息密度优先于句式完整。

## 验收（validate.py 自动跑）

- 字段齐全且长度在区间内
- `nums` 每条含 `\d`
- `task`/`problem` 不含评价词表（有限/不足/一般/较差/存疑/但/然而）
- `task` 不含方法名（与 title 里大写缩写做交集检查）
- 全文数字个数 ≥ 3

不通过的卡片进 `regen/rejected/`，附失败原因，不进站点。

## 迁移策略

1. 先跑 pilot：抽 200 篇（按 relevance 分层，含全部 ≥8 分的），人工过 20 篇定稿 prompt。
2. 全量替换时**不删 v1 字段**，只做字段追加 + `v: 2` 标记；站点渲染按 `v` 分支，可随时回退。
3. `one_line` 在 v2 里保留，作为列表页的"结论"列；列表页副标题改显示 `task`。
